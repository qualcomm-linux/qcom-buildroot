## Validating the OP-TEE PAS path

The rootfs bundles a small validation set behind `qcom-tests` (an interactive
runner in `/usr/bin`): **ADSP FastRPC**, **CDSP FastRPC** and a **VIDEO**
encode→decode round-trip. All three exercise the OP-TEE PAS (Peripheral
Authentication Service) authenticate/reset that OP-TEE performs when the kernel
brings up a remoteproc. `fastrpc_test` comes from `BR2_PACKAGE_FASTRPC_EXT`
(github.com/qualcomm/fastrpc).

Firmware and DSP runtime are staged into the `BR2_ROOTFS_OVERLAY` overlay
(`kodiak/overlay/`) from two sources:

1. **Remoteproc / codec firmware** — staged by the `linux-firmware` make target,
   a prerequisite of `buildroot` (so it is always baked into the rootfs), pinned
   to `FW_SRCREV`:
   - `qcom/qcm6490/{adsp,cdsp}.mbn` (+ `*.jsn`) — the remoteproc images whose
     load triggers the OP-TEE PAS path. The base RB3Gen2 DTS `firmware-name`
     points at `qcom/qcs6490/` (no flat image), so `kodiak-el2.dtso` overrides
     the adsp/cdsp `firmware-name` to `qcom/qcm6490/`.
   - `qcom/qcs6490/QCS6490-RB3Gen2-tplg.bin` — the AudioReach ADSP topology.
   - `qcom/vpu/` plus the `qcom/vpu-2.0/venus.mbn` WHENCE symlink — venus codec fw.
2. **DSP runtime** (`fastrpc_shell*` + skels + `conf.d/*.yaml` mapping the DT
   model → `DSP_LIBRARY_PATH`) from `linux-msm/dsp-binaries` at `DSP_TAG` →
   `/usr/share/qcom/…`. Staged by **`make fetch-blobs`, which must run before
   `buildroot`** (the sandbox script `0.create.new.sandbox.sh` does this).
   `FW_SRCREV` is pinned to the same dated release as `DSP_TAG` so the firmware
   and runtime match.
3. **QRTR userspace daemons** — `qrtr-ns` (service registry), `tqftpserv`
   (TFTP-over-QRTR; the DSP rootPD reads its runtime) and `rmtfs` (serves the
   peripherals' persistent EFS storage over QRTR), launched by the overlay init
   scripts `S40qrtr` / `S41tqftpserv` / `S42rmtfs`. `rmtfs` requires eudev (the
   device manager, so `/dev/qcom_rmtfs_mem*` and the partition symlinks exist)
   and the `rmtfs_mem` reserved region kept by `kodiak/patches/linux/`.

`CONFIG_QCOM_FASTRPC` and the remoteproc/rpmsg/glink chain are built in by
`linux-defconfig` (the build sets `CONFIG_MODULES=n`).

On target:

```
qcom-tests                 # menu: pick ADSP / CDSP / VIDEO / all
# or directly:
fastrpc_test -d 3 -U 0     # -d 3 = CDSP, -d 0 = ADSP
```

A passing run means OP-TEE executed the PAS reset sequence correctly.

**Status:** CDSP FastRPC and the VIDEO round-trip pass. ADSP FastRPC passes on
the vendor BSP kernel (7.2.0); this build matches that BSP on firmware, DSP
runtime, qrtr-ns/tqftpserv/rmtfs, the AudioReach tplg and the `rmtfs_mem`
region — but on the manifest-pinned kernel (7.1.0-rc6) the ADSP glink never
posts FastRPC RX intents ("intent request timed out"), so ADSP FastRPC does not
yet complete. This is a kernel-version gap; ADSP is expected to work once the
pinned kernel moves to 7.2.0.
