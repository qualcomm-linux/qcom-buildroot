dTPM + DRTM with Xen

The discrete TPM of features/lemans/security/dtpm, plus the pieces of an Arm DRTM (DEN0113) dynamic launch: TF-A BL31 as the dynamic configuration environment (DCE), Xen as the dynamically launched measured environment (DLME), and OP-TEE as the S-EL1 SPMC that owns the TPM and reaches Xen's guests over FF-A only.

Branch: features/lemans/security/dtpm-drtm, a feature branch of qcom-buildroot on top of features/lemans/security/dtpm. Its manifest takes Linux (on top of the dTPM kernel), TF-A, OP-TEE, Xen and the test definitions from the features/lemans/drtm branch of each project, and lemans.mk builds the FF-A firmware, BL31 with the DRTM service and the Xen boot by default.

Building it

Same flow as the dTPM branch; only the branch name changes. XEN=y and DRTM=y are the defaults here.

mkdir sandbox.lemans && cd sandbox.lemans
repo init -u https://github.com/qualcomm-linux/qcom-buildroot \
          -b features/lemans/security/dtpm-drtm -m manifests/lemans.xml
repo sync -j4 --no-clone-bundle

cd build
make -j8 toolchains
make all                  # OP-TEE SPMC, BL31 (SPMD + DRTM), U-Boot, Linux dom0, Buildroot, Xen, efi.bin
make bootimage            # tz.mbn + uefi.elf
make flash-lava           # package + flash a lab board (lemans/lava/flash-lava-xen.yaml)

# optional: a fingerprint every stage prints at boot
make all bootimage LOCALVERSION=-mybuild-001
XEN=n DRTM=ngives back the plain OP-TEE boot of the dTPM branch: SPD=opteed, OP-TEE on the SMC ABI, Linux started directly from the UKI.

The boot

  • FF-A only. BL31 runs SPD=spmd SPMD_SPM_AT_SEL2=0 and OP-TEE CFG_CORE_SEL1_SPMC=y. Xen does not mediate the OP-TEE SMC ABI; dom0 and the guests reach OP-TEE (and through it the dTPM) via Xen's FF-A mediator.
  • Consoles. Xen owns the GENI debug UART (console=dtuart dtuart=serial0); dom0's console is hvc0 and the getty runs on /dev/console.
  • DRTM. DRTM=y builds BL31 with DRTM_SUPPORT=1; lemans.mk initializes the libeventlog and Mbed TLS submodules of TF-A it needs.

DRTM: where it stands

The target follows the tboot model: the DCE measures the DLME into PCR 17/18 at locality 4 through the secure-world dTPM, and Xen measures dom0 at locality 2 into PCR 19.

The validated DRTM scenario

What is proven on the board today is the DCE half of the launch: BL31 answers the DEN0113 calls, refuses malformed launches, turns on DMA protection and enters a DLME at NS-EL2 with every non-secure DMA stream blocked. The run below (LAVA job 557870, rb8-hyd-02) uses this branch's TF-A and OP-TEE with a test U-Boot whose preboot issues the DRTM SMCs, and a small test DLME that reports what it sees; neither test piece is built by this branch.

  1. Cold boot

    BL31 sets up the DRTM service next to the SPMD; OP-TEE starts as the S-EL1 SPMC. AOP, SAIL and CPUCP are DMA-capable but trusted (non-host platforms). The GPU SMMU is only engaged when GPU CX is on; at this point it is off. 
    NOTICE:  BL31: v2.15.0(release):QCDFP-261110-3044
INFO:    DRTM service setup
WARNING: DRTM: the platform includes trusted DMA-capable devices (non-host platforms)
INFO:    DRTM: GPU CX off (GDSCR 0x22f001), GPU SMMU not engaged
I/TC: OP-TEE version: QCDFP-261110-3044 ...

  2. Discovery and the error record

    From U-Boot: DRTM_VERSION, DRTM_FEATURES (TPM, minimum memory, DMA protection, boot PE, TCB hashes, DLME image authentication), then DRTM_SET_ERROR and DRTM_GET_ERROR round trip.

  3. Malformed launches are refused

    DRTM_DYNAMIC_LAUNCH with a parameter block that is not 4 KiB aligned, and with a DLME placed inside secure memory, both fail without touching the SMMUs. 
    ERROR:   DRTM: parameters structure is not 4-KiB-aligned
ERROR:   DRTM: DLME region lies within secure memory

  4. DMA protection

    On a valid launch BL31 puts both SMMU-500 instances into abort-all: every stream mapping group of the apps SMMU (224) and of the PCIe SMMU (64) is handed to the non-secure side with client bypass off and unmatched streams faulting (NSCR0 CLIENTPD cleared, USFCFG set). The DLME has to program the SMMUs before any device can reach memory again. 
    INFO:    SMMUv2 @0x15000000: 224 of 224 stream mapping groups Non-secure, NSCR0 0x290400
INFO:    SMMUv2 @0x15200000: 64 of 64 stream mapping groups Non-secure, NSCR0 0x240400

  5. DLME entry

    The DLME starts at NS-EL2 (CurrentEL 0x8) with x0 pointing at the DLME data (header version 1) and finds the SMMUs as BL31 left them, with no fault recorded. 
    DLME_START QCDFP-261110-3044 x0=0x00000000e0100000 x1=0x0000000000100000 CurrentEL=0x0000000000000008

  6. A DMA attempt is blocked

    The DLME rings the UFS host controller doorbell with a transfer request. The UFS DMA never reaches memory: the apps SMMU records an unidentified stream fault (GFSR 0x80000002) for stream ID 0x100, the UFS controller. 
    DLME_APPS_FAULT_AFTER_UFS GFSR,GFSYNR0,GFSYNR1,GFAR 0x0000000080000002 0x0000000000000000 0x0000000000000100 0x0000000f536cb800
DLME_DONE QCDFP-261110-3044
The rest of the stack under XenLAVA job 557881 (rb8-hyd-03) boots the same firmware and the kernel of this branch with the test rootfs: the tpm2 tests from dom0 (locality 4 refused to the normal world), OP-TEE xtest (37772 subtests, 0 failed), and the Xen tests (dom0, parallel xl guests, OP-TEE over FF-A from dom0 and from a guest).

Glossary

DRTMDynamic Root of Trust for Measurement: a late, measured launch of a small trusted environment, independent of the boot chain before it (Arm DEN0113; the x86 counterparts are Intel TXT and AMD SKINIT).
DCEDynamic Configuration Environment: the code that performs the launch, here the DRTM service in TF-A BL31.
DLMEDynamically Launched Measured Environment: what gets launched and measured, here Xen.
SPMD / SPMCThe TF-A dispatcher and the secure partition manager of FF-A; with SPMD_SPM_AT_SEL2=0 OP-TEE is the SPMC at S-EL1.
FF-AArm Firmware Framework for A-profile: the messaging ABI between the normal world, the hypervisor and the secure world.
LocalityTPM access level. PCR 17 and 18 are reset only from locality 4 and cannot be extended from locality 0 or 1; PCR 19 is extended from locality 2, the DLME's own measurements.
